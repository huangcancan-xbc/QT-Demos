# Demo 说明

>因为暂时不太会用 C++ 写下载脚本，但是反观 python 来说就容易很多，所以就让我想到了 C++ 和 python 联合编译，但是在探索的过程中发现了 QProcess，于是就有了这个 Demo，需要注意的是它并不属于 C++ 和 python 的联合编译，仅仅是父子进程关系，但依然让我学到挺多，至于 C++ 和 python 的联合编译估计就要到后面了……

这是一个基于 Qt（C++）+ Python（yt-dlp）的桌面视频下载 Demo。用户在 Qt 界面输入视频链接后，Qt 通过 `QProcess` 启动 Python 脚本 `python/download_video.py` 执行下载，并将后端输出实时回显到日志面板。

核心流程：
1. Qt 前端校验输入链接并解析 Python 解释器/脚本路径。
2. Qt 使用 `QProcess` 启动 Python 子进程并传入参数（`--url`、`--output-dir`）。
3. Python 使用 `yt-dlp` 下载视频，并将进度、成功/失败信息输出到 stdout/stderr。
4. Qt 监听子进程输出与退出码，更新日志和状态标签。

## 1. 存在的问题

-   程序找 python 相关的路径直接是写成了相对路径而且写死了，当路径不符合时，程序无法工作。

-   视频默认输出目录就是构建目录（即当前程序的根目录），即视频默认输出路径是 `build/...-Debug`

-   网络类失败较常见，比如 X/Twitter 链接会出现 TLS handshake timeout（握手超时），属于真实下载失败，当前重试能力不足。

-   ffmpeg 缺失时画质策略退化，没有检测到 ffmpeg 时会降级为单文件流，下载成功率较高但可能损失质量。

-   虽然已经做了一些字符处理，但仍存在部分字符显示乱码或者其他问题。

-   进程残留导致二次编译失败风险，若 `Video_Downloader.exe` 未被正确结束，会导致链接阶段 `Permission denied`（`collect2/ld returned 1`），这个问题不清楚是什么导致的，解决办法很直接：直接 kill 进程，重新启动，代码层面还不知道如何避免/解决。
